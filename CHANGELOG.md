# Changelog

## Unreleased
- **Exit codes (Elon, 2026-10-18):** any error or FAIL anywhere in a check run is non-zero. 1 = a detector FAILed; 2 = nothing FAILed but something errored: a detector ERROR, a WARN (a child that raised, crashed on a signal, exited non-zero, timed out or never reached its crash point), an unhandled exception in the driver (reported as detector `driver`), or bad `--input`/`--context` JSON. 0 only when every detector is PASS or SKIP. Hung children time out (`AGENTSIGNAL_CHILD_TIMEOUT_S`, default 120) and are reported instead of raising. A `kill_before_checkpoint` child that errors is now a WARN instead of being skipped silently; a replay/inspect child with no result line is an ERROR instead of a crash. The v0.3.2 multi-interrupt case (scalar resume rejected by LangGraph, exited 0) now exits 2. Tests: `tests/test_exit_codes.py`.
- Fixtures: `subgraph_parallel_graph:build_keyed` (#9315 graph with a stable key per charge) passes every detector on 1.2.15 and 1.2.16 (board 64); `safe_graph.py` docstring corrected (state check, no idempotency key); `langchain-ai/langgraph#9315` typo fixed.
- **Fix links are free pages only** (Elon, 2026-10-18): no FAIL or fix link points at a Pro template any more. LangGraph double-execution FAILs (baseline, kill_resume, kill_before_checkpoint) link to https://tryagentsignal.com/guides/langgraph-interrupt-resume-twice/; OpenAI Agents double-execution and replay FAILs link to https://tryagentsignal.com/guides/duplicate-tool-calls-after-resume/ (same targets as Action v1.3.2). LangGraph lost_on_restart / replay and OpenAI Agents lost_on_restart keep their free templates. `--upload` prints the CLI's own free link per detector instead of the server's `url` (prod's table still maps double execution to Pro templates). The scan's closing link is one switch in `links.py`: `LEDGER_LIVE = False` uses the free guide (`Fix (free guide): …/guides/duplicate-tool-calls-after-resume/`); **next patch: set `LEDGER_LIVE = True` once https://tryagentsignal.com/templates/side-effect-ledger/ serves 200 (board 54)**, which switches it to `Fix (free, copy-paste): …/templates/side-effect-ledger/`. Tests: `tests/test_fix_links.py`.
- **Fix (crash test, async effects):** the effect watcher called `async def` effects without awaiting them, so the ledger row held a coroutine object (a new value per call: a ledger short-circuit on replay looked like a duplicate) and the crash-at-N kill landed before the effect had run. With several `--effect` targets, an async ledger-wrapped tool showed a false duplicate (board 54 X2, `billing:acharge`). The watcher (`detectors/_effects.py`, shared by both children) now awaits coroutine functions and sync callables that return an awaitable, records only once the effect really ran, then kills. Sync effects behave as before. Tests: `tests/test_async_effects.py` (async effect counted once; async ledger short-circuit on replay is not a duplicate, LangGraph and OpenAI Agents; async naive effect still FAILs).
- **Fix (LangGraph kill_resume flakiness):** under LangGraph's default async durability, the hard kill right after the effect sometimes lands after the previous task's pending writes were saved but before the next checkpoint was. `get_state()` then reports `next=()` although the run never finished, and the resume child treated that as "done", so a naive graph randomly PASSed. The child now resumes when the checkpoint has a next node **or pending tasks** (`invoke(None)` applies the saved writes and continues, as any app resuming the thread would). The kill point itself was already deterministic (right after the effect's ledger row is fsynced); the race was in the checkpoint write. Tests: `tests/test_lg_resume_lost_checkpoint.py` builds the lost-checkpoint state deterministically; fixture `tests/fixtures/split_naive_graph.py`.
- **Static scan:** `agentsignal check --scan PATH` finds side effects that re-run on resume, using Python's `ast` only (never imports or runs your code, no network). LangGraph rules AS101–AS105 (effect before `interrupt()`, effect in a loop with `interrupt()`, post-approval effect without an idempotency key, resume path without a ledger lookup, approval handler deliverable twice) and OpenAI Agents rules AS201–AS204 (approved tool without a key, tool without a key, RunState resumed twice in a handler, approval never persisted). A `key=` kwarg counts as idempotency evidence when it's built from a run, thread, call or tool-call id or a stable hash of one; random keys are flagged "key is random per call".
- Output is `file:line`, function, one-line message, rule id and confidence; a result with findings ends with "N tools will re-run on resume" ("may re-run" when they are all medium confidence) and the free fix link (see "Fix links" above), and a clean scan ends with "No re-run risks found by static scan." and no link. Long paths go on their own line instead of running into the message. The "Prove it" hint names `<module>:build` only when that file defines `build()`. `--format json` (or `--json`) gives `{"scan": {...}}` with stable ordering.
- The scan header and `scan.frameworks.langgraph` show the **project's** langgraph version and where it came from, e.g. `langgraph 1.2.15 (requirements.txt)`, using the same lookup as AS106–AS108 (not the version installed next to the scanner, which in CI is usually the newest). With no pin or lockfile it shows `langgraph version unknown (no pin found)` (JSON `version`/`source` null); the installed version is never shown. openai-agents has no project lookup yet, so no version is shown for it. JSON fields: `version`, `spec`, `source` (plus `versions` when files resolve differently).
- Speed: the AST is walked once per file with cached children, and files are pre-filtered on an actual `import`/`from` of langgraph, agents or google.adk before decoding and parsing. A 2,000-file repo of real framework files scans in ~1.4 s (was ~4.5–5 s); tests assert < 3.5 s.
- Exit 1 on any high finding, 0 otherwise (`--strict` fails on medium too), 2 on usage error. Unparseable files are listed as skipped. `--effect-names`, `--exclude`, `--include-tests`, `--verbose`, inline `# agentsignal: ignore[...]` and `[tool.agentsignal.scan]` in pyproject.toml (suppressions are counted).
- `--effect` is now required only for the crash test; `--scan` needs neither `--effect` nor `--graph`. `--scan` with `--graph/--agent` scans first, then runs the crash test.
- Tests: `tests/test_scan.py` covers every rule, the board 53 acceptance fixtures, a precision corpus of the public templates (`tests/fixtures/scan/corpus/`), false-positive guards, suppression/config, skipped files, a no-import guard, golden terminal/JSON output, and two 2,000-file speed checks (synthetic and real framework files, < 3.5 s).
- **Fix:** when the baseline run errors (setup, import or graph/agent failure), `agentsignal check` now exits 2 with a clear "baseline run failed" error on stderr. It used to exit 0, so a broken setup passed CI. Tests: `tests/test_baseline_error.py`.
- **Ledger leases:** if a watched effect raises an exception named `EffectInFlight` while `double_execution.kill_resume` or `double_execution.kill_before_checkpoint` resumes, it counts as a clean refusal: no duplicate was observed, so the detector passes with the note "in flight; retried after lease with the same provider key" (board 54, decision G7). Matched by class name, so there's no import dependency. Any other exception on resume is still a WARN. Tests: `tests/test_effect_in_flight.py`, fixture `tests/fixtures/inflight_graph.py`.
- **Several pending interrupts:** the LangGraph driver used to resume with a single `Command(resume=value)`, which LangGraph rejects when several interrupts are pending, so the check errored on graphs with parallel approvals. It now resumes with `{interrupt_id: value}` (including interrupts inside subgraphs), answering one at a time by default or all at once with `--multi-interrupt map`. New fixture `tests/fixtures/subgraph_parallel_graph.py` (langgraph#9315): answered one at a time, langgraph 1.2.15 reports the double execution (6 charges for 3 approvals) and 1.2.16 passes the baseline (3 charges). Tests: `tests/test_multi_interrupt_driver.py`.
- **Version-aware scan rules** for langgraph bugs fixed in 1.2.16: AS106 (#9315, side effect after `interrupt()` in a parallel node of a compiled subgraph), AS107 (#9322, `Command(resume=..., update=...)` with a node that interrupts more than once) and AS108 (#9314, `durability="exit"` with 3+ parallel interrupts). The langgraph version comes from the nearest `uv.lock`, `requirements*.txt` or `pyproject.toml` (no imports, no resolving). High when it pins or resolves < 1.2.16; medium with "fixed in 1.2.16; pin >=1.2.16" when no version is found; nothing when it requires >= 1.2.16. AS101 stays unconditional. Tests: `tests/test_scan_versions.py`.

## 0.3.1 (2026-10-16)
- **`--upload` (Signal Pro):** posts the `--json` report to `https://tryagentsignal.com/api/check/runs/` with `Authorization: Bearer $AGENTSIGNAL_API_KEY` (override the URL with `AGENTSIGNAL_API_URL`) and prints the returned `run_id` and fix links (detector, status, url). The body follows the server contract: `{report:{framework, results:[{detector, status, detail}], env}, repo, commit_sha, framework, version}`; statuses map to PASS/FAIL/ERROR/SKIP (WARN counts as FAIL, anything unknown as ERROR), and `repo`/`commit_sha` come from `GITHUB_REPOSITORY`/`GITHUB_SHA` or the local git checkout when available. 401, 403, 400, 413, 429 and network errors print a clear message and never change the exit code; add `--upload-strict` to exit 3 when the upload fails on an otherwise passing run. With no key, `--upload` prints a one-line hint and the check runs exactly as before. With `--json`, upload messages go to stderr so stdout stays pure JSON.
